# Codex Design Bridge 0.4.3

完整版本：`0.4.3+codex.20260731090627`

## 本版重点

0.4.3 修复“在 Figma 删除元素后，插件显示没有新修改，但源码元素仍存在”的问题。

- 删除已映射的内联 SVG，或删除 SVG 内最后一个可见路径使映射容器变空，都会生成独立 `nodeDelete` 并删除对应源码元素。
- 删除已映射的图片，或由同源 `<img src="./graphic.svg">` 展开的 SVG，会删除对应 `<img>` 元素但保留资源文件。
- 当父节点仍存在时，完整删除已映射 Frame、文字、SVG 或图片子树会删除准确匹配的源码元素；子节点不会重复提交。
- 新增、移动、部分改写层级以及无法确认安全源码范围的删除仍保存为待处理结构差异。
- 源码侧再次校验元素类型和删除上下文；不安全的 JSX/模板上下文会保留为 `unsafe_delete_context`。
- 结构基线版本升级，避免删除动作继续被折叠进笼统 `structure` 差异。
- 复制一个已映射的 Frame 子树时，即使 Figma 一并复制了旧插件数据，也会为副本分配新的稳定 ID，生成 `nodeClone`，先在源码中克隆对应元素，再应用副本的文字与颜色。
- 复制节点的 `x`/`y` 不直接写入源码；新元素作为原元素的相邻兄弟插入，由现有 CSS 布局决定位置。
- 仅修改 Figma 图层名称不再制造待处理结构差异；无法确认安全源码范围的克隆仍保留给 Codex。
- Figma 本地握手协议升级到 9，旧插件窗口会收到版本不匹配提示。

## 验证结果

`npm.cmd run check`：50/50 通过。

新增回归覆盖：

- Figma 删除已映射 SVG 后只生成一个 `nodeDelete`，不再附带重复的整页结构差异。
- 空 SVG、图片以及完整 Frame/文字子树可从 HTML/JSX 源码安全移除。
- 位于 `return <element>` 等不安全 JSX 上下文中的容器删除会保留为待处理差异。
- 复制已映射按钮后，原按钮保持不变，源码新增带独立稳定 ID 的按钮，并在同一批次应用副本文字与填充色。

## 升级与复测

1. 完整退出 Codex/ChatGPT，包括后台进程。
2. 解压完整发布包并双击 `Install Codex Design Bridge.cmd`。
3. 重新打开 Codex，创建新任务，确认工作台显示 `v0.4.3`。
4. 关闭并重新运行 Figma 中的 Codex Design Bridge 开发插件。
5. 重新生成 Figma 设计后再测试删除或复制；已经在旧结构基线上发送过的复制/删除无法从新版本自动反推，需要以修正后的源码重新更新一次 Figma 设计再重做。

真实 Codex/Figma 桌面端到端验收仍需完成；自动化通过不等于运行中的旧任务已经热更新。
