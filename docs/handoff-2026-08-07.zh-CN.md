## 接手后的验证顺序

1. 执行 `npm ci`。
2. 执行 `npm run check`，要求语法检查和 Node 测试全部通过；Windows 上允许明确标注的 macOS 专用用例跳过。
3. 校验 `codex-plugin/codex-design-bridge/` 的插件清单和 `.mcp.json`。
4. 用当前源码生成精确候选，更新 cachebuster，并通过插件安装流程重装。
5. 完全退出 Codex 后重新打开，在全新任务中确认 `design_workspace` MCP 工具和内嵌 Apps UI 来自当前构建。
6. 在 Figma Desktop 重新运行 CDB 开发插件，完成页面导入、圆角/布局等属性回传、跨父级移动、自动验证和安全 Undo。
7. 按 `figma-smoke-test.md` 记录真实桌面证据后，再标记发布验收完成。

## 当前发布门禁

- 自动化测试只证明源码逻辑，不证明 Codex 桌面宿主已经暴露 MCP 工具或挂载 Apps UI。
- 普通 localhost 预览不等于内嵌 CDB 工作台。
- Figma 中只出现少量元素时，优先检查唯一 `<main>` 捕获边界、稳定 `data-codex-id` 和运行时 DOM 生成。
- 圆角、布局、位置或层级回写必须经过真实页面验证；不能只比较消息回执。
- 插件升级后必须新建 Codex 任务，并关闭后重新运行旧的 Figma 插件窗口。

## GitHub 发布建议

1. 在此目录初始化 Git 仓库并提交源码。
2. 先创建私有仓库；确认许可、作者信息和公开范围后再转为公开。
3. 不要把 `releases/*.zip` 直接提交到源码历史，二进制候选使用 GitHub Releases。
4. 首次推送后检查 GitHub Actions 的 Windows/Node 22 工作流。
5. 项目目前未声明开源许可证；如需开放复用，应由仓库所有者明确选择许可证后再添加。
