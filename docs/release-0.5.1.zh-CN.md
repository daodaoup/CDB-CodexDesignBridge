# Codex Design Bridge 0.5.1

完整版本：`0.5.1+codex.20260803153436`

## 本版重点

0.5.1 把快速写回从“逐文件尽力修改”升级为可验证、可回滚、可安全撤销的事务，并为内嵌工作台增加真实挂载证据。

- Codex 与 Figma 中的用户可见插件名称统一为 `CDB`；内部插件 ID 继续使用 `codex-design-bridge`，保证原 marketplace 和升级路径不变。
- Codex composer、插件详情页和深色模式 logo 使用新的 128×128 透明 PNG 图标；图标文件纳入安装器核心哈希校验。
- 每批 Figma 快速写回先完成路径校验、源文件哈希预检、备份和临时文件暂存，再统一提交。
- 任一文件发生并发变化、写入失败或写后校验失败时，已提交文件自动回滚；失败批次不会报告为已应用。
- 事务记录保存到项目 `.figma-sync/transactions/`，默认保留最近 20 次记录。
- 工作台 Undo 直接调用 `undo_last_design_patch`，只撤销最近一次 Design Bridge 事务，不再依赖模型提示。
- 如果事务完成后文件又被用户或其他工具修改，Undo 会返回冲突并保持文件原样。
- Apps UI 挂载后主动调用 `report_design_workspace_mounted`；状态中的 `workspaceMounted` 和 `uiMountedAt` 可区分“预览服务已启动”与“Codex 内嵌工作台已显示”。
- 启动技能明确禁止把外部 localhost 页面当作内嵌工作台的替代成功状态。
- 修正 macOS 专用个人源码发现测试在 Windows 上读取真实用户目录的问题。
- Windows 与 macOS 安装器把事务模块纳入发布包完整性与运行缓存哈希校验。
- Windows 安装器发现残留的 ChatGPT/Codex 后台进程时会列出 PID，并在用户输入 `Y` 后自动关闭再继续；同时自动发现桌面版内置 Codex CLI，修复“完全退出仍反复阻塞”和缺少 `codex.cmd` 的安装失败。

## 安全边界

- Undo 只处理由 Design Bridge 记录的最近一次可撤销事务。
- 源文件当前哈希必须与事务提交后的哈希一致；存在后续编辑时拒绝覆盖。
- 事务只允许写入项目根目录内的明确文件，不接受越界路径或重复目标。
- 0.5.1 没有扩大动态 JSX、跨父容器移动、组件语义或危险 SVG 的自动写回范围。

## 发布前仍需完成

自动化通过不等于运行中的 Codex 已加载新插件。正式标记桌面可用前仍需：

1. 在 macOS 对同一正式 ZIP 运行安装器只读校验。
2. 完整退出 Codex 后安装，新建任务并确认 MCP Apps 工具与源码、缓存版本一致。
3. 确认 `workspaceMounted: true`，连续验证现有项目和新草稿的内嵌工作台启动。
4. 在真实 Figma 桌面完成属性、结构、SVG、事务失败和 Undo 冲突往返。
