# Codex Design Bridge 0.5.0

完整版本：`0.5.0+codex.20260731143428`

## 本版重点

0.5.0 把常见 Figma 结构编辑从笼统 `structure` 差异升级为可验证的源码操作。

- 新建普通 Frame、文字和带图片填充的节点时，生成稳定 `data-codex-id`，通过 `nodeInsert` 写入 HTML/JSX；图片导出为 PNG，保存到项目的 `codex-design-assets/`。
- 新建按钮 Frame 会根据图层名称生成语义化 `<button type="button">`；其他容器使用受限的安全标签集合。
- 已映射 Frame、文字、图片和 SVG 子树都可复制；副本及其后代获得独立稳定 ID，并通过 `nodeClone` 写入源码。
- 已映射 Frame、文字、图片和 SVG 子树可通过 `nodeDelete` 删除。
- 同一源码容器内、全部具有稳定选择器的直接子元素可通过 `nodeReorder` 排序；移动引起的 `x/y` 变化不再重复进入待处理项。
- 宽度、高度、透明度、显示/隐藏、字体家族、字重、斜体、行高、字距、水平/垂直文字对齐、大小写和文字装饰进入快速 CSS 写回。
- 结构迁移版本升级；旧窗口中尚未发送的普通新增、矢量新增和重复稳定 ID 副本会在新协议下重新识别。
- Figma 本地握手协议升级到 10，旧插件窗口会收到版本不匹配提示。
- 新增 macOS 双击安装器，提供发布包校验、首次本地 marketplace 引导、旧版本备份、Codex CLI 重新注册、运行缓存哈希核对、安装报告和失败回滚。

## 安全边界

- 排序只在目标源码容器除目标映射子元素外不含其他文字或标签时自动执行；交错的未映射内容保留为 `unsafe_reorder_context`。
- 新增结构必须位于具有稳定源码选择器的已映射父节点下，并且项目必须能确定唯一 CSS 文件。
- 条件渲染、循环、动态模板、跨文件组件组合和无法完整定位的源码结构继续交给 Codex。
- 现有普通元素的自由 `x/y` 定位、阴影、模糊、变量、Variant 和原型交互不在本版自动写回范围内。

## 验证结果

Windows 既有基线为 `npm.cmd run check` 53/53 通过。加入 Mac 安装器回归后，macOS 完整套件为 56 项通过、0 项失败、3 项 Windows 专用跳过。

插件清单校验通过；工作区、个人插件源码和新运行缓存的清单及八个核心文件 SHA-256 全部一致。正式 ZIP 已完成反向解压，解压后的安装器 `-CheckOnly` 校验结果为 `package-valid`。当前仍在运行的应用可能继续显示旧 `0.1.0+codex.20260729103158` 注册，完整退出并新建任务后才会加载本版。

新增回归覆盖：

- HTML 中插入含文字和 PNG 图片的按钮子树，并按 Figma 顺序重排。
- JSX 中插入、重排和删除映射子元素。
- 交错未映射文字的源码容器拒绝危险排序且保持原文件不变。
- Figma 新增普通 Frame/文字/图片、通用文字复制、安全删除和排序均生成明确结构操作，不再附带笼统 `structure`。
- 排序产生的 `x/y` 变化被抑制，宽高、透明度和完整文字排版属性仍独立发送。

## 升级与复测

1. 完整退出 Codex/ChatGPT，包括后台进程。
2. 解压完整发布包并双击 `Install Codex Design Bridge.cmd`。

5. 点击一次“更新 Figma 设计”建立协议 10 的结构基线，然后分别测试新增、复制、删除、排序和文字排版。
